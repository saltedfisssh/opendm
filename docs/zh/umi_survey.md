# UMI 及相关工作调研：数据处理与坐标系设计

> 调研时间：2026-09。聚焦 Universal Manipulation Interface (UMI) 及其衍生工作在**数据采集/处理流程**与**坐标系定义与转换**两方面的技术方案，帮助判断哪些方案可以借鉴到 DM05 的数据管线中。

## 1. 原始 UMI（基线参照）

**硬件**：3D 打印的平行夹爪 + 软手指，唯一传感器是手持的 GoPro（155° 鱼眼），利用鱼眼视野而不做去畸变（去畸变会拉伸边缘、压缩中心关键信息）。夹爪两侧加装物理镜片，为 GoPro 提供隐式双目/立体线索。GoPro 内置 IMU 用于在快速运动下保持鲁棒跟踪。夹爪开合由弹簧机构 + 触发器控制，宽度通过机械结构编码。

**定位/SLAM**：早期版本依赖视觉惯性 SLAM（如 ORB-SLAM3，或 RealSense T265）处理鱼眼图像+IMU，恢复夹爪的 6-DoF 全局轨迹；后续变体也用 ArUco/AprilTag 辅助。论文实测该单目惯性 SLAM 方案的绝对轨迹误差（ATE）约为 6.1mm / 3.5°（位置/旋转），相对位姿误差（RPE）约为 10.1mm / 0.8°——这一精度水平是后续 RoboPocket、HiFi-UMI 等工作试图改进的直接基准（对比 RoboPocket 单机 2.8mm/0.4°）。

**数据清洗**：论文与后续工作强调对 SLAM 跟踪失败/漂移片段的剔除（人工或自动检测跟踪质量），但原始论文本身着墨不多，后续 UMI 衍生工作（RoboPocket、HiFi-UMI 等）把这一环节做得更系统。

**动作/观测表示（核心贡献）**：
- **相对轨迹（relative-trajectory）动作表示**：把未来一段时间的动作定义为相对于**当前**末端执行器（EE）位姿的一串 SE(3) 变换，而不是相对世界坐标系的绝对位姿，也不是相对"上一步"的增量（delta，会累积误差）。这样策略天然与"全局标定"解耦——不需要知道机器人基座在世界中的位置。
- 历史观测（proprioception）用同样的相对轨迹表示：把过去几帧的 EE 位姿也表示为相对当前帧的相对位姿，观测窗口设为 2 时即可隐式提供速度信息。
- 旋转用**6D 连续旋转表示**（Zhou et al. 的 continuous 6D rotation），而非欧拉角/轴角，避免角度环绕和万向节死锁；6D 向量通过 Gram-Schmidt 正交化还原为旋转矩阵：给定预测的 a₁, a₂ ∈ ℝ³，归一化 a₁ 得 b₁，将 a₂ 对 b₁ 正交化并归一化得 b₂，再叉乘得 b₃，组成 [b₁, b₂, b₃]。
- 双臂场景下，额外把"两个夹爪之间的相对位姿"也喂给策略，这被证明对双臂协调至关重要。

**坐标转换链（Coordinate transform chain）**：
- 帧定义：相机帧（GoPro，鱼眼模型）→ 夹爪/工具帧（camera 与 gripper tip 之间为固定 mechanical 外参，需标定）→ SLAM 世界帧（每次采集时任意初始化，通常取第一帧相机/IMU 位姿为原点）→ 部署时的机器人基座帧。
- 关键设计：**用相对位姿彻底消解"任意的 SLAM 世界原点"和"未知的机器人基座标定"**——策略只学习"从当前 EE 出发要走到哪"，不学习"在世界/机器人坐标系里的绝对目标"。这意味着即使 SLAM 世界帧原点是任意的、即使没有做机器人基座的外参标定，学出来的策略依然可部署；也因此机器人在执行中移动底盘不会破坏任务表现，使 UMI 框架天然适配移动操作平台。
- 手眼标定：相机→夹爪的外参通过棋盘格/标定板等标准流程离线标定一次，之后固定复用（"calibration-free" 指的是不需要**机器人到世界**的标定，而不是不需要相机到夹爪的标定）。

**局限**：单目/单相机视觉惯性 SLAM 在遮挡、动态场景、弱纹理环境下容易丢失跟踪；后续大量工作（LiDAR 融合、多鱼眼、外部光学跟踪、手机深度相机）都是在补这个短板。

## 2. HiFi-UMI（2026.07）

**定位思路的根本转变**：不再用**腕部相机做主 SLAM**（容易被遮挡、漂移），而是引入一个**头戴式**采集装置，用双目-惯性 SLAM 做全局定位；两只手上的夹爪各贴一个**基准标记方块（fiducial marker cube）**，由头戴相机观测来定位双手，位姿是"原生测得"而非"事后从腕相机重建"。

**硬件**：头戴双目+IMU 用于全局轨迹；每个夹爪配两个非平行广角鱼眼相机，单手视野覆盖约 200°；所有相机/IMU/编码器/夹爪信号共用**微秒级 GPIO 硬件触发**，跨传感器时间误差 < 40 μs。

**数据处理管线**：六阶段自动化流程，核心两步是 (1) Reconstruction：离线双目惯性 SLAM 处理头戴与手部影像，生成全局一致轨迹；(2) Simulation Retargeting：每条重建轨迹在物理仿真器里重放做校验。管线整体轨迹重建成功率约 98%，全身控制（WBC）重放校验成功率约 98%。

**规模**：源语料 > 20,000 小时、432 万条 episode、480+ 场景；公开子集为精选 2,000 小时。工作空间局部末端精度可达 **33mm**（论文摘要原文表述为"与 VR 手柄跟踪相当"的精度水平），且**不依赖外部动捕基础设施**。

**坐标转换链**：头戴 SLAM 提供全局相机轨迹（世界帧原点=头戴装置初始位姿）；每个夹爪的位姿通过头戴相机对其标记方块的观测直接解出（本质是 PnP/marker-based 位姿估计），再结合标记方块与夹爪 TCP 的固定机械外参得到夹爪工具帧位姿。这种"双手位姿都在同一头戴帧下被直接观测"的设计，规避了传统 UMI"每个夹爪各自做 SLAM、再事后对齐"的漂移累积问题，属于**手眼/双手标定问题的结构性简化**：不需要独立标定每个夹爪相机的外参漂移，因为定位主体从"夹爪自身"转移到了"外部头戴观察者"。仿真重放（retargeting）阶段隐含了从人手轨迹到目标机器人运动学可行域的验证/转换，但论文没有透露具体 IK/重定向数值细节（论文未公开的部分）。

## 3. VISTA（2026.06）

**核心问题**：UMI 数据用于训练大模型 VLA 存在两个"分布不匹配"：(1) 腕部鱼眼视角畸变严重、局部视野，对预训练 VLM 是 OOD；(2) 人采集的轨迹常违反机器人运动学限制/发生自碰撞/超出控制器带宽，教会策略"物理不可行"的动作。

**硬件**（采用 Lumos Robotics 的 **FastUMI Pro** 平台，约 600g 一体化手持装置）：主鱼眼相机居中，另有两只辅助鱼眼相机 + 一个深度相机，构成四目视觉系统，即使中心视野被夹爪手指遮挡或纹理缺失也能保持跟踪；夹爪宽度由内部编码器测量、手柄扳机控制。

**定位**：融合两路独立跟踪——外部 **Vive Tracker**（基站式 6-DoF 光电跟踪）与机上相机阵列的实时视觉惯性 SLAM，融合后位姿精度约 3mm，对瞬时遮挡鲁棒。

**目标机器人适配（embodiment-specific 环节）**：预训练后，用约 5,000 条真实 UMI demo，通过跨本体 **Mink**（逆运动学库）重放打分并过滤，剔除运动学违规/自碰撞风险/重放保真度差的轨迹，再微调到具体部署机器人和任务。实验证明：相当比例的原始 UMI 轨迹因运动学限制/碰撞/跟踪误差而**无法**在真实机器人上重放，验证了这一过滤步骤的必要性；物理校验分数越高，部署效果越好。

**坐标转换的关键设计**：为避免"重新标定视觉帧"，VISTA 让**机器人侧的末端相机与手持采集装置使用完全相同的相机型号/安装方式**，机器人侧夹爪指尖几何和相机外参与手持装置保持一致（只做机械适配，不改变相机-指尖几何关系），从而保证"部署时的视觉观测分布"与"训练时的视觉观测分布"一致，策略不需要重新标定视觉坐标系即可跨本体迁移。该方案已在 RealMan、AC one、Galaxea R1 Pro 三种双臂平台上验证。部署侧用 Zenoh 作为分布式通信中间件。

## 4. RDT2（2026.02）

**目标**：验证"把 UMI 数据规模做到极限，能否实现对未见机器人本体的**零样本**部署"。收集 10,000+ 小时演示，用增强的、embodiment-agnostic UMI 装置。

**硬件的根本改动——放弃视觉 SLAM，改用外部红外光学跟踪**：原始 UMI 是 3D 打印结构，强度不足以支撑长期高频采集，RDT2 改用尼龙66+玻纤复合材料 CNC 精密加工；更关键的是，**弃用了容易在无纹理室内环境失效的 SLAM 定位**，改为使用 **HTC VIVE Tracker 3.0**（红外光学定位）跟踪末端 6-DoF 位姿。

**动作表示**：预测短时相对动作片段（24 步 × 20 维/步），来自双目腕部相机 RGB + 语言指令；用轻量 Residual VQ 对动作离散化（RDT2-VQ），或用 flow-matching 动作专家（RDT2-FM）。

**坐标转换/跨本体的关键逻辑**：由于 Vive Tracker 提供的是**统一的外部世界坐标系**下的末端 6-DoF 位姿（不依赖视觉 SLAM 的漂移、不依赖每次采集时任意初始化的相机世界帧），且**人手持装置与机器人夹爪共享同一套末端几何/跟踪基准**，从而最大程度缩小了"人手 vs 机械臂"的具身差异（embodiment gap）。具体硬件上，采集端和部署端使用**完全同型号**的 Hikrobot MV-CS016-10UC 工业相机（eye-in-hand 安装方式一致）；机器人侧执行用 ZhiXing CTAG2F120 平行夹爪，手持采集装置则做了一个**非驱动的同几何复刻件**（同样的开合几何和运动范围，但无电机驱动，靠操作者手动控制开合以匹配机器人夹爪的运动学范围）——这与 VISTA"硬件同构"路线本质相同。此外还采用了**home pose 对齐**技巧：部署时把机器人初始化到一个"视觉上复现手持采集装置平均起始视角"的固定初始姿态（Home Pose），以进一步对齐推理时和训练时的状态分布。论文的定位是"无需遥操作、无需目标机器人数据、无需微调"（"totally plug-and-play"），但同时也承认零样本部署仍需要"正确的硬件标定"（correct hardware calibration）——即**手眼/坐标系标定仍是部署前提**，只是因为硬件设计统一了末端跟踪基准而大幅降低了标定负担，并不是完全消除。已验证零样本部署到双臂 UR5e 与 Franka Research 3。

## 5. HyVLA-0.5 / Hy-Embodied-0.5-VLA（2026.06）

**架构**：4B MoT（Mixture-of-Transformers）VLM 骨干 + flow-matching 动作专家，用 **delta-chunk** 动作表示：预测连续步之间末端的**增量**运动，声称能把策略学习和"具体本体的运动学"解耦，缩小优化搜索空间，为跨本体后训练提供统一底座。

**UMI 数据（Hy-UMI-10K）**：自研的**指尖式（fingertip）UMI 采集装置**，用**光学动作捕捉系统**跟踪，宣称亚毫米精度，覆盖 70+ 任务，10K+ 小时（2K+ 小时公开）。论文明确指出传统 UMI 手持装置"笨重、无法捕捉指尖级力传递"，是其改用指尖式采集 + 光学动捕的动机。

**跨本体处理**：论文把跨具身差距拆成三层——(1) embodiment gap：人手与机器人运动空间的差异；(2) control gap：不同动力学/执行器带来的控制差异；(3) perception gap：人类第一视角与机器人机载相机视角的差异。UMI 预训练解决第一层的数据规模问题，之后分两条并行后训练路线迁移到不同本体（JAKA K1、Astribot S1 等 4 个真实平台），其中部分本体**仅用 UMI 数据微调、不使用该本体的遥操作数据**即可部署，被视为"高保真 UMI 数据提供了强的、与本体无关的操作先验"的证据。

**坐标系细节**：与总览表初判不同——论文实际给出了显式的跨本体坐标映射公式（第 5.1 节 "Embodiment-Agnostic Platform Mapping"）。设 T_{G_t}^{W} 为采集/执行时刻 t 末端（gripper）相对世界帧 W 的位姿，T_{G_{t+k}}^{G_t} 为未来第 k 步相对当前末端的相对变换（即 delta-chunk 动作），则：
  - 固定基座机械臂：T_{G_{t+k}}^{W} = T_{G_t}^{W} · T_{G_{t+k}}^{G_t}
  - 浮动基座人形/移动本体（世界帧下机器人自身也在运动，需额外用机身相机帧 C 做一次转换）：T_{G_{t+k}}^{C} = (T_{C}^{W})^{-1} · T_{G_t}^{W} · T_{G_{t+k}}^{G_t}
  这与原始 UMI 的"相对当前 EE 位姿"范式完全一致，只是显式区分了固定基座和浮动基座两种情形；动作空间本身是每个末端 10 维（3 维平移 + SO(3) 前两行的 6 维旋转表示 + 1 维夹爪），且都相对 chunk 起始时刻的 EE 位姿定义。光学动捕系统本身提供统一的全局跟踪坐标系，规避了视觉 SLAM 的世界帧任意性问题——这与 RDT2 的 Vive Tracker 思路同源（都是"用外部主动式跟踪代替被动视觉 SLAM 以获得统一坐标基准"）。

## 6. Xiaomi-Robotics-1（2026.07）

**规模**：100K+ 小时 UMI 采集轨迹用于预训练，覆盖 1,700+ 场景（家庭/商业空间/工业场所/户外）；后训练混合"自采真机数据（7,200+ 小时，真实家庭环境采集，如整理沙发、分类鞋柜、收纳厨具）+ 过滤后的开源机器人数据 + 高质量 UMI 数据"共 10K+ 小时跨本体数据。

**关键坐标系设计——显式的末端帧朝向统一**：论文明确指出，为了在预训练和后训练数据集中对齐不同本体（包括 UMI 数据和各类真机数据）的动作空间，**统一了所有机器人数据和 UMI 数据中末端执行器坐标系的朝向（orientation）约定**。这是与前述工作（依赖硬件层面的一致性，如 VISTA 的相同相机、RDT2 的统一跟踪装置）不同的路线：Xiaomi-Robotics-1 走的是**数据层/表示层的显式坐标系归一化**，即在数据处理阶段把所有来源的末端姿态旋转部分重新表达到统一的坐标约定下，而不依赖采集硬件本身的一致性。

**自动标注**：开发了可扩展的自动标注管线，为轨迹片段标注描述"场景状态转移"的自然语言，为动作学习提供更精确的语言条件。

**动作空间公式**：论文给出了显式的动作定义——设 t 时刻末端相对基座帧位姿为 T_t^{EE}_{Base}，未来 t+i 时刻目标末端位姿为 T̂_{t+i}^{EE}_{Base}，则动作 a_{t+i} = (T_t^{EE}_{Base})^{-1} · T̂_{t+i}^{EE}_{Base}，即相对基座帧下的末端 delta 位姿——与原始 UMI"相对当前 EE"的范式一致，只是把参照系明确为机器人基座帧而非任意 SLAM 世界帧。

**未公开细节**：论文给出了上述基础的相对动作公式，但未进一步公开"末端帧朝向统一"这一跨本体归一化步骤的具体数学变换（是否类似 CalibAll 的 TCP 重定义、y/z 轴约定），也未说明 UMI 采集端使用的具体硬件/SLAM 方案细节。

## 7. Noe-0 / Noematrix（2026.08，技术预览）

未找到与"Noe-0"直接对应的公开技术细节（搜索确认这更像是内部代号或预览性发布，暂无正式论文）。但 Noematrix 公司本身在 UMI 路线上有两款已披露的数据采集装置，可作为背景参考：

- **CoMiner**：外骨骼式"伴随采集"装置，带高精度角度编码器，可同步采集图像、关节角、力/力矩、运动轨迹等多模态数据，可适配多种机器人平台，支持遥操作和"in-the-wild"两种采集模式。
- **RoboPocket**（单独论文，2026.03，arXiv:2603.05504）：用手机（iPhone）自带 SLAM+深度（LiDAR）+IMU 做位姿跟踪，相比原始 UMI 的"手动标定、反复操作"大幅简化易用性；解决**多机协同标定**问题——多手机之间共享时间戳与 SLAM 坐标系，空间对齐靠 peer-to-peer 的地图（world-map）合并，时间对齐把多传感器时钟同步到 5ms 精度；单机跟踪精度 2.8mm/0.4°（优于传统 UMI 惯性-单目 SLAM 的 6.1mm/3.5°），双机共享地图配置下 4.0mm/0.7°；夹爪硬件设计目标是与 **Robotiq 2F-85** 保持严格的几何同构（而非通用夹爪），并用 ESP32+磁编码器采集夹爪宽度；采集时**实时**在线校验 SLAM 稳定性和运动学可行性（区别于原始 UMI 的事后离线质检）。

**结论**：Noe-0 本身对外公开的技术细节非常有限，博客性质为主，"不需要机器人数据"更接近前瞻性宣传口径；但其背后的 CoMiner/RoboPocket 路线代表了"降低采集硬件门槛（用手机而非专用相机+计算单元）+ 实时质检 + 多设备协同标定"这一确定的技术方向，值得关注其正式论文/后续披露。

## 8. GEN-1 / Generalist AI（2026.04，公司博客）

**技术披露程度低**，核心内容以性能宣传为主（99% 成功率 vs 此前 64%，速度快 3 倍，折盒 200 次/装箱 1800 次/服务扫地机器人 200 次无需人工介入等）。

**数据路线**：明确指出 GEN-0/GEN-1 的基础模型**完全不用机器人数据**训练，而是用"低成本可穿戴设备"采集的人类完成各类任务的数据；博客原文确认规模为"**超过 50 万小时**的高保真物理交互数据"（half a million hours of high-fidelity physical interaction data，较 GEN-0 有显著增长）。强调 UMI 这类"人直接戴戴具操作"的方式比 VR 遥操作更能保留人的"物理直觉"（引用 Jim Fan 观点），且因为没有遥操作的延迟/力反馈缺失问题，数据本身动作更流畅。

**Post-training**：每个新任务仅需**约 1 小时**真机数据即可达到宣称的高成功率——这是 GEN-1 区别于 UMI-only 部署（如 RDT2/HiFi-UMI）的关键点：**明确依赖少量真机数据做任务级适配**，不追求 UMI→真机零样本直接部署。

**坐标系细节**：完全未公开。这是一份纯营销性技术博客，没有任何 SLAM/标定/坐标转换层面的可验证信息，需要谨慎对待其技术可信度，仅作为行业动态参考。

## 9. 跨工作共性趋势总结

### 9.1 数据采集硬件的演化路径
1. **原始 UMI**：GoPro + 鱼眼 + 物理镜片 + IMU，纯被动视觉惯性 SLAM，单一夹爪自身做定位。
2. **手机化**（RoboPocket/Noematrix）：用智能手机原生 SLAM+LiDAR+IMU 代替专用相机+计算单元，大幅降低成本与标定门槛，且能做多机协同。
3. **多目/头戴式**（HiFi-UMI、VISTA）：把"定位主体"从单一腕部相机升级为多鱼眼/头戴双目+标记方块，用冗余视角和外部观察结构解决遮挡和漂移问题。
4. **外部主动跟踪**（RDT2 的 Vive Tracker、HyVLA-0.5 的光学动捕）：彻底放弃纯视觉 SLAM，用外部红外/光学主动跟踪系统提供统一、无漂移的全局坐标基准，代价是需要固定的跟踪基站/动捕空间，牺牲了"随地采集"的便携性以换取精度和跨本体一致性。

这是一个清晰的权衡轴：**便携性/可扩展性（纯视觉 SLAM、手机化）↔ 精度/跨本体一致性（外部主动跟踪）**。DM05 若要扩展 UMI 类数据采集，需要先明确自己在这条轴上的取舍。

### 9.2 动作/观测表示：相对位姿几乎是行业共识
几乎所有工作（原始 UMI、UMI-3D、VISTA 后续再处理、Xiaomi-Robotics-1、RDT2、HyVLA-0.5 的 delta-chunk）都采用某种"相对末端位姿"表示，而非依赖固定全局坐标系的绝对动作：
- 相对表示的核心公式（原始 UMI / VLA Foundry 形式化）：设锚点时刻末端位姿 T_ref ∈ SE(3)，未来时刻动作位姿 T_t ∈ SE(3)，则相对动作 T_t^rel = T_ref⁻¹ · T_t。
- 旋转部分几乎统一用 **6D 连续旋转表示 + Gram-Schmidt 正交化**还原为旋转矩阵，避免欧拉角/轴角的奇异性问题。
- 这一约定的根本原因：**相对表示天然规避了"SLAM 世界帧原点任意"和"机器人基座外参未标定"两个问题**，是 UMI 能够"免标定部署"的数学基础，而不是靠某种更好的标定技术消除了标定需求。

### 9.3 跨本体（embodiment gap）坐标统一的三条技术路线
调研范围内的工作可归纳为三种不重叠但常被组合使用的路线：

1. **硬件同构路线**（VISTA）：让手持采集装置和机器人末端使用相同相机型号/安装方式/指尖几何，使视觉观测分布在训练和部署间保持一致，从根源上避免"重新标定视觉坐标系"。RoboPocket 的"夹爪几何严格匹配 Robotiq 2F-85"也是同一思路。
2. **统一跟踪基准路线**（RDT2、HyVLA-0.5）：用同一套外部主动跟踪系统（Vive Tracker/光学动捕）同时服务人手采集和机器人执行，坐标系天然一致，无需事后转换，但需要专门的跟踪基础设施。
3. **数据层显式归一化路线**（Xiaomi-Robotics-1，以及独立论文 CalibAll "Unify Robot Actions in Camera Frame" 2511.17001）：不依赖硬件一致性，而是在数据处理阶段把不同来源（UMI、各类真机遥操作数据）的末端位姿**重新表达到统一约定**下——例如统一末端坐标系朝向（Xiaomi-Robotics-1），或更彻底地把所有动作转换到**相机坐标系**下表示（CalibAll：先把 flange 位姿转换为夹爪指尖 TCP 位姿，因为不同夹爪几何不同、flange 位姿不代表实际抓取点；再统一 TCP 局部坐标系约定——z 轴沿夹爪前向、y 轴沿夹爪闭合方向；最终用相机外参把动作统一表达在相机帧下，使动作跨本体具有一致的几何语义）。这条路线正在被多个 2026 年新工作采用（ACE-Ego-0、Qwen-RobotManip、JoyAI-RA 0.1 等），是目前最活跃的技术方向，值得重点关注。

### 9.4 "零样本 UMI→真机部署"声称的成色
- 明确宣称零样本、且给出可信技术支撑的：RDT2（统一跟踪硬件）、HiFi-UMI（头戴+标记方块，任务级但架构上支持）、原始 UMI（任务级 BC，非大模型规模）。
- 明确不追求零样本、承认需要少量真机数据的：GEN-1（每任务 1 小时）、Xiaomi-Robotics-1（7.2K+ 小时真机数据混合）、VISTA（5K 条真实 demo 做 embodiment-specific 过滤微调）。
- HyVLA-0.5 介于两者之间：部分本体可仅用 UMI 微调部署，部分本体仍需常规 SFT。

**审慎提示**：即使"零样本"的工作（RDT2、GEN-1 类宣传），论文/博客中也普遍承认部署仍需"正确的硬件标定"或"少量适配数据"，"零样本""无需机器人数据"等表述需要按上下文（是指预训练阶段不用机器人数据，还是指部署时完全不需要任何机器人侧调整）仔细甄别，不能一概而论。
